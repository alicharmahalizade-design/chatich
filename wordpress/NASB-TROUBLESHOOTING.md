# عیب‌یابی نصب افزونهٔ «هسته دوریان»

## ساخت بستهٔ نصب

```bash
wordpress/build-plugin.sh      # خروجی: wordpress/dist/dorian-core.zip
```

زیپ را دستی از فایل‌منیجر هاست یا ابزارهای استریمی نسازید — دلیلش در بخش «۱» آمده.

## نتیجهٔ بررسی نسخهٔ ۱.۳.۱

خودِ بسته سالم است. موارد زیر بررسی و تأیید شد:

| بررسی | نتیجه |
|---|---|
| ساختار زیپ (یک پوشهٔ ریشه `dorian-core/`) | ✅ |
| سلامت آرشیو (`unzip -t`) | ✅ |
| سرآیند افزونه (`Plugin Name` و `Version`) | ✅ پارس می‌شود |
| سینتکس هر ۱۱ فایل PHP | ✅ بدون خطا |
| سازگاری با PHP 7.2 (مطابق `Requires PHP`) | ✅ سینتکس جدیدتر ندارد |
| لود شدن افزونه و ساخته‌شدن هر ۹ کلاس | ✅ بدون خطای مرگبار |
| وجود همهٔ فایل‌های `require` شده | ✅ |
| وجود همهٔ اسِت‌های ارجاع‌شده (فونت/CSS/JS/SVG) | ✅ |
| BOM یا خروجی اضافه قبل/بعد از تگ PHP | ✅ ندارد |
| کلاس/تابع تکراری | ✅ ندارد |
| فایل زائد مک (`__MACOSX`, `.DS_Store`) | ✅ ندارد |

پس اگر خطای «پرونده‌ای یافت نشد» می‌گیرید، علت **سمت سرور یا نحوهٔ بسته‌بندی** است.

## خطای واقعیِ مشاهده‌شده روی dorianstudio.ir

نصب‌کننده این را نشان می‌دهد:

```
گشودن بستهٔ فشرده شده...
در حال نصب افزونه...
پوشهٔ هدف از قبل موجود است.
/home2/dorianst/domains/dorianstudio.ir/public_html/wp-content/plugins/dorian-core
```

این «Destination folder already exists» است، نه «پرونده یافت نشد». یعنی یک نصبِ
قبلی، پوشه را روی دیسک جا گذاشته و وردپرس حاضر نیست رویش بنویسد.

همراهش این نشانه هم هست: دو نسخهٔ قدیمی در فهرست افزونه‌ها می‌مانند و حذف از
پیشخان اثری ندارد — بعد از ریلود باز هم هستند. چون افزونه هیچ‌وقت فایل نمی‌نویسد و
آپدیتر خودکار ندارد (بررسی شد)، این یعنی **PHP اجازهٔ حذف آن پوشه‌ها را ندارد** —
معمولاً وقتی پیش می‌آید که فایل‌ها با FTP یا کاربری غیر از کاربرِ PHP ساخته شده‌اند،
یا کوتای دیسک پر است. وردپرس حذف را «موفق» گزارش می‌کند ولی پوشه سرِ جایش می‌ماند.

نکتهٔ مرتبط: وردپرس ۵.۵ به بعد معمولاً گزینهٔ «جایگزینی نسخهٔ فعلی با نسخهٔ
بارگذاری‌شده» را پیشنهاد می‌دهد. اینکه اینجا پیشنهاد نداده یعنی پوشهٔ موجود سرآیندِ
معتبر افزونه ندارد — یعنی از یک استخراجِ نیمه‌کاره جا مانده است.

### راه‌حل

اول پوشه‌های جامانده را پاک کنید، بعد نصب کنید:

**روش الف — فایل‌منیجرِ DirectAdmin (مطمئن‌ترین):**
1. File Manager → مسیر `public_html/wp-content/plugins/`
2. **همهٔ** پوشه‌هایی که با `dorian` شروع می‌شوند را پاک کنید
   (مثلاً `dorian-core`، `dorian-core-1`، `doriancore`).
3. پیشخان → افزونه‌ها را ریلود کنید؛ نسخه‌های قدیمی باید ناپدید شوند.
4. حالا `dorian-core.zip` را بارگذاری و نصب کنید.

**روش ب — ابزار پاک‌سازی:** `tools/dorian-cleanup.php` را کنار `wp-config.php`
بگذارید و در مرورگر بازش کنید. مالک و سطح دسترسی هر پوشه را گزارش می‌دهد و حذفشان
می‌کند؛ اگر نتوانست، دقیقاً می‌گوید کدام فایل مقاومت کرده تا به پشتیبانی هاست بگویید.
**بعد از کار حتماً این فایل را از سرور پاک کنید.**

**روش ج — نصب دستی:** پوشهٔ `dorian-core` را از زیپ درآورید و مستقیم با FTP در
`wp-content/plugins/` بگذارید، بعد فعالش کنید. اصلاً درگیر نصب‌کنندهٔ وردپرس نشوید.

اگر حتی فایل‌منیجر هم نتوانست پاک کند، مسئله مالکیت فایل است و فقط پشتیبانی هاست
حلش می‌کند (`chown` به کاربر `dorianst`).

## علت‌های محتمل، به‌ترتیب احتمال

### ۱) زیپ با ابزار استریمی ساخته شده (data descriptor)

زیپی که با کشیدن پوشه در فایل‌منیجر هاست یا برخی ابزارهای آنلاین ساخته می‌شود،
اندازه و CRC هر فایل را به‌جای سرآیندِ محلی، در یک *data descriptor* بعد از دادهٔ
فایل می‌نویسد. وردپرس آرشیو را با `ZipArchive::CHECKCONS` باز می‌کند و libzip های
قدیمی چنین آرشیوی را ناسازگار می‌شمارند؛ آن‌گاه وردپرس به PclZip برمی‌گردد که
خطای `PCLZIP_ERR_MISSING_FILE (-4)` می‌دهد — همان «پرونده یافت نشد».

زیپ ۱.۳.۱ که بررسی شد، دقیقاً همین وضع را داشت: هر ۱۶ فایل با data descriptor و
سرآیند محلیِ صفر. روی PHP 8.4 / libzip 1.7.3 هنوز باز می‌شد، ولی روی هاست‌های
قدیمی‌تر نه. `build-plugin.sh` این حالت را حذف می‌کند و خروجی را با هر دو مسیرِ
وردپرس تست می‌کند.

### ۲) پوشهٔ مقصد از قبل وجود دارد

اگر نسخهٔ قبلی نصب است، ابتدا از پیشخان غیرفعال و حذفش کنید، یا از طریق FTP پوشهٔ
`wp-content/plugins/dorian-core/` را پاک کنید، بعد نصب کنید.

### ۳) پوشهٔ موقت یا دسترسی نوشتن

- `wp-content/upgrade/` و `wp-content/plugins/` باید قابل نوشتن باشند (۷۵۵).
- اگر `upload_tmp_dir` در PHP تعریف نشده یا وجود ندارد، آپلود بی‌صدا شکست می‌خورد.
- **فضای دیسک/کوتای هاست پر باشد** هم دقیقاً همین خطا را می‌دهد — اول این را چک کنید.

### ۴) محدودیت آپلود PHP

بستهٔ فعلی ۱۶۰ کیلوبایت است، پس معمولاً مشکل‌ساز نیست؛ ولی اگر
`upload_max_filesize` یا `post_max_size` خیلی پایین باشد یا `file_uploads` خاموش
باشد، `$_FILES` خالی می‌رسد و وردپرس می‌گوید پرونده‌ای نیست.

### ۵) ModSecurity / فایروال هاست

نام فایل `doriancore1.3.1.zip` چند نقطه دارد و بعضی WAF ها آن را «پسوند دوگانه»
می‌بینند و آپلود را می‌بلعند. نام خروجی `dorian-core.zip` است تا این حالت پیش نیاید.

## راه دور زدن: نصب دستی

اگر آپلود از پیشخان همچنان کار نکرد، این روش همیشه جواب می‌دهد:

1. زیپ را روی کامپیوتر خودتان باز کنید.
2. پوشهٔ `dorian-core` را با FTP یا فایل‌منیجر داخل `wp-content/plugins/` بگذارید.
3. پیشخان → افزونه‌ها → «هسته دوریان» را فعال کنید.

نام پوشه باید دقیقاً `dorian-core` بماند.
